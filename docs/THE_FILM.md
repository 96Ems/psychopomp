# The optchat film — how it is made, and how to regenerate it

The film is hosted with the plugin it explains:
[opencode2-plugin-optchat · media/optchat-v5.mp4](https://github.com/96Ems/opencode2-plugin-optchat/blob/main/media/optchat-v5.mp4)
(2:26, 1920×1080, 60 fps, −17.7 LUFS). It is generated entirely
from this repository: a Rust scene, a narrated script, and the local TTS/STT stack
described in [LOCAL_TTS_STT.md](LOCAL_TTS_STT.md). No paid API, no cloud renderer.

## What is in the repository

| piece | path |
|---|---|
| the scene (Rust, one file) | `scenes/optchat/src/main.rs` |
| the plan it writes | `scenes/optchat/optchat.reel.json` |
| the script that was recorded | `scenes/optchat/narration/script.json` |
| the recorded clips + word timings | `scenes/optchat/narration/<clip>.mp3` + `.words.json` |
| the timing manifest | `scenes/optchat/narration/narration.json` |
| the film | `docs/optchat-v5.mp4` |

The scene is written *against* the narration rather than the other way round: every
visual beat waits for a phrase ("the log outgrows the window", "one sub-agent per
subject"), so the film re-times itself if the voice is re-recorded. Phrase lookups
panic on a wrong word, which is deliberate — a silently missing beat is worse than
a failed build.

## Regenerate it

```sh
export PATH="$HOME/.cargo/bin:$HOME/.bun/bin:$PATH"

# 1. the voice and the word timings (setup: docs/LOCAL_TTS_STT.md)
WHISPER_CMD="$HOME/.venvs/tts/bin/python $PWD/scripts/stt-words.py" \
STT_MODEL=nemo-parakeet-tdt-0.6b-v2 \
bun scripts/narrate.ts scenes/optchat/narration/script.json

# 2. build the reel from the scene
cargo run -p psychopomp-optchat

# 3. look at the plan before spending the render (see below)
cargo run --release -- plan validate scenes/optchat/optchat.reel.json
cargo run --release -- plan inspect  scenes/optchat/optchat.reel.json
cargo run --release -- plan frame scenes/optchat/optchat.reel.json 68 /tmp/frame.png --theme opencode
bun scripts/sheet.ts scenes/optchat/optchat.reel.json 6,31,68,92 --theme opencode --out output/sheet.png

# 4. render (about 55 min for 2:26 on a GTX 960M)
cargo run --release -- plan render scenes/optchat/optchat.reel.json output/optchat.mp4 --theme opencode
```

Step 3 is not optional. A contact sheet read at full size is the only cheap way to
notice a clipped footer, an unreadable box or a missing connector *before* the
render; single frames via `plan frame` are how you check the few moments the sheet
cannot show clearly.

## Anchors: the part that bites

Every beat is keyed to a phrase in the recorded audio, and the recogniser does not
write what you expect. Two rules, learned the hard way:

- **check every anchor against the clip's `words.json` before writing code.** A
  wrong phrase panics the build, and a plausible-looking phrase is often wrong —
  "one subagent per subject" is recorded as "one sub agent per subject".
- **never anchor on the product name, and never on a phrase that touches a
  number.** The recogniser writes the product as "opchat", and it glues digits:
  the transcript really contains `fixed95,000` and `tokens,12 times less`.

`plan inspect` prints each segment's span. A segment whose lines start noticeably
before its clip does is the signature of an anchor that matched late.

## Host prerequisites (Ubuntu 22.04, the machine this was rendered on)

- **FFmpeg 4.4** — `alimiter=...:latency=1` exists only from FFmpeg 5, which is
  why `crates/psychopomp-render/src/encode.rs` in this fork drops it (see the
  commit that added the local narration stack);
- **ImageMagick**, for `scripts/sheet.ts` — plus a `magick` shim if the package
  only ships `convert`;
- a GPU with Vulkan (the render here runs on a GTX 960M).
